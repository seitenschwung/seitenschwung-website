Von Philipps Tastatur in deinen Browser.

Hier steht offen, womit seitenschwung.com gebaut ist, was jede Änderung bestehen muss und wo die Seite wohnt. Die Fachbegriffe stehen jeweils klein darunter, falls du sie nachschlagen willst.

Der Weg einer Änderung

  1. Philipp

    Schreiben

    Jede Änderung landet als nachvollziehbarer Schritt im Archiv. Am laufenden Server wird nichts von Hand gebastelt.

    Git, GitHub

  2. automatisch

    Prüfen

    Ein Testroboter startet die Seite, klickt sie auf Desktop und Handy durch und misst nach.

    GitHub Actions, Playwright, axe, Lighthouse

  3. automatisch

    Verpacken

    Genau die geprüfte Fassung wird als fertiges Paket abgelegt. Online geht später nur dieses Paket.

    Docker, nginx, GitHub Container Registry

  4. automatisch

    Ausliefern

    Durch einen verschlüsselten Tunnel geht das Paket an unseren Server. Der Server braucht dafür keinen offenen Zugang.

    Tailscale, Coolify

  5. für dich

    Online

    Die Seite läuft in einem Rechenzentrum in Nürnberg und kommt verschlüsselt bei dir an.

    Hetzner, Let’s Encrypt, HTTP/3

Was jede Änderung bestehen muss.

Bevor etwas online geht, muss die neue Fassung durch diese Prüfungen. Jedes Mal, auch für ein einzelnes Komma.

  • Läuft ohne Administratorrechte.Der Webserver arbeitet als einfacher Benutzer, nicht als root.
  • Startet abgeschottet.Schreibgeschützt, ohne Sonderrechte, mit höchstens 256 MB Speicher.
  • Meldet sich gesund und nennt seine Version./healthz und /version.txt müssen antworten.
  • Funktioniert auf Desktop und Handy.Browser-Tests mit Playwright, einmal bei 1440 × 900, einmal als Pixel 7.
  • Hat keine schweren Barrieren.axe prüft nach WCAG 2.1 AA. Ernste Fehler stoppen alles.
  • Schafft in Lighthouse mindestens 90.Bei Barrierefreiheit, Best Practices und Suchmaschinen.
  • Hat vollständige Rechtstexte.Fehlt eine Pflichtangabe in Impressum oder Datenschutzerklärung, wird nicht veröffentlicht.

Fällt ein Punkt durch, bleibt die alte Fassung online.

Und wenn es online doch hakt?

Vor jeder Auslieferung merkt sich die Pipeline, welche Version gerade läuft. Antwortet die neue danach nicht sauber, holt sie die alte automatisch zurück.

  1. Fassung A läuft.Die Pipeline notiert sich ihre Version.
  2. Fassung B antwortet nicht.Der Gesundheitscheck nach dem Start schlägt fehl.
  3. Fassung A ist zurück.Automatisch, ohne dass jemand eingreifen muss.

Woraus die Seite selbst besteht.

Bausteine
HTML, CSS und etwas JavaScript. Kein Framework, kein Baukasten, keine Plugins.
Schriften
Zodiak und Rethink Sans liegen auf unserem eigenen Server, zusammen 60 KB. Dein Browser fragt dafür nicht bei Google an.
Bilder
Echte Screenshots der Kundenseiten, als WebP verkleinert.
Bewegung
Die Blätter im Einstieg zeichnet ein Canvas, Bild für Bild. Wer im System weniger Bewegung eingestellt hat, sieht sie ruhig.
Tracking
Keins. Keine Cookies, keine Analyse-Werkzeuge, darum auch kein Cookie-Banner.
Verbindung
Verschlüsselt mit einem Zertifikat von Let’s Encrypt, auch über HTTP/3.
Server
Hetzner, Rechenzentrum Nürnberg. Die Seite liegt in Deutschland.
Schutz
CrowdSec erkennt auffällige Zugriffe und sperrt sie. Server-Logfiles werden nach 14 Tagen gelöscht.
